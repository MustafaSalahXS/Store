## Getting Started

## Financial Metrics

### Key Performance Indicators (KPIs)

**Revenue Metrics:**
- **Gross Revenue**: Total before refunds
- **Net Revenue**: Revenue after refunds
- **Revenue Growth**: Month-over-month %
- **Revenue per Customer**: Average spend

**Order Metrics:**
- **Total Orders**: Number of orders
- **Order Growth**: % increase over time
- **Average Order Value**: Revenue ÷ orders
- **Repeat Customer Rate**: % of returning customers

**Payment Metrics:**
- **Payment Success Rate**: % successful
- **Average Payment Time**: How long to complete
- **Payment Method Distribution**: % per method
- **Failed Payment Rate**: % failed

**Refund Metrics:**
- **Total Refunds**: Amount refunded
- **Refund Rate**: Refunds ÷ revenue
- **Refund Reasons**: Most common reasons
- **Refund Processing Time**: Average days to process

**Product Metrics:**
- **Top Products**: By revenue
- **Product Revenue**: For each product
- **Product Performance**: Sales trends
- **Margin Analysis**: Profit per product (if cost entered)

### Industry Benchmarks

Compare your metrics to industry standards:

- **E-commerce avg refund rate**: 5-10%
- **Payment success rate target**: 95%+
- **Average order value**: Varies by product
- **Customer retention**: 30-40% repeat

### Alerts & Thresholds

Get notified of issues:

1. Set custom thresholds:
   - Alert if refund rate > 10%
   - Alert if payment success < 90%
   - Alert if revenue drops 20%

2. Receive alerts via:
   - In-app notification
   - Email
   - SMS (if enabled)

3. Review alerts regularly

## Reconciliation

### Bank Reconciliation

Verify bank matches records:

1. Click "Reconciliation"
2. Select payment method (Paymob, Vodafone, etc.)
3. Select date range
4. View:
   - **Expected Amount**: What system shows
   - **Actual Amount**: What bank shows
   - **Difference**: If any mismatch
   - **Status**: Matched, unmatched, partially matched

5. If unmatched:
   - Review transactions
   - Check for:
     - Timing differences (payments in transit)
     - Failed transactions marked as succeeded
     - Duplicate transactions
     - Discrepancies in amounts

6. Investigate discrepancies
7. Document findings
8. Contact payment provider if needed
9. Mark as reconciled

### Payment Verification

Verify payments received:

1. Click "Verify Payments"
2. See list of pending payment verifications
3. For each payment:
   - Check order amount
   - Verify payment method
   - Confirm transaction ID
   - Check date received
   - Verify in payment provider dashboard

4. Mark as verified when confirmed
5. Or mark as issue if discrepancy

## FAQ

**Q: How often is data updated?**
A: Real-time for new orders/payments. Reports updated hourly.

**Q: Can I access data from multiple years?**
A: Yes, select any date range. No limits on historical data.

**Q: How do I know if payment failed?**
A: Check Transaction History and filter by "Failed" status. Review error details.

**Q: How long to process refund?**
A: Varies by method. Card: 3-5 days. Wallet: 1-2 days. Cash: Immediate.

**Q: Can I modify reports?**
A: No, but you can export and customize in Excel.

**Q: Who can access financial data?**
A: Only accountants and store admin. Data is encrypted.

**Q: How do I handle discrepancies?**
A: Document details and contact admin or payment provider.

**Q: Can I set budget limits?**
A: No, but you can set refund/failure alerts.
